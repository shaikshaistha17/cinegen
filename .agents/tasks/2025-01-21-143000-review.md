# Part 3 AI Intelligence Implementation Review

AI-assisted brief drafting, deterministic validation, and transparent creator matching with evidence-based scoring.

This implementation adds intelligence features to CineGen's marketplace: brands can describe campaigns in natural language and receive structured suggestions, briefs are stress-tested for common gaps, and creators are matched to briefs with fully explained scores. The system preserves deterministic baselines while optionally enhancing with AI where configured.

**Watch for:** Rate limiter resets on restart (confirmed—in-memory storage), missing aspect ratio contradiction check has been correctly removed (multi-format is valid), and AI timeout implementation uses real AbortController (confirmed—10s limit with proper cleanup).

**Verdict**: APPROVED

## High-level view

The brief drafting flow calls Gemini with a 10-second timeout, retries once on failure, validates the output structure, and falls back to rule-based generation if the provider fails—user input is preserved in all cases via the `preservedIdea` field. Rate limiting is enforced at the API boundary using an in-memory sliding window (10 requests per 60 seconds per user+endpoint), scoped only to AI-powered endpoints. The validation system now includes six deterministic checks including conflicting specs (Short-form Video >60s), missing revision allowance, and budget/timeline feasibility warnings labeled as estimates. Creator matching builds a deterministic baseline from skills overlap (0-40 pts), verified tools (0-30 pts), budget fit (0-20 pts), and availability (0-10 pts), with portfolio items matched by content type and tools—unknown data is treated as unknown, never invented. The scoring factors are exposed as human-readable explanations, not just percentages. API keys remain server-side only, all external calls have timeouts, and the code never simulates a successful AI response on failure.

## Provider safety and API key isolation

All AI provider calls happen server-side in `/lib/ai/briefDrafter.ts` and `/lib/ai/creatorMatcher.ts`. The Gemini API key is read from `process.env.GEMINI_API_KEY`, never exposed to the client. No `NEXT_PUBLIC_` prefix appears in any AI integration code. API routes check for authentication via session cookies before processing requests.

Timeouts are implemented with `AbortController`, not promises that can hang indefinitely. The brief drafter creates a controller, sets a timeout with `setTimeout(() => controller.abort(), timeoutMs)`, passes `controller.signal` to the fetch call, and clears the timeout after the request completes or throws. The creator matcher's optional AI note follows the same pattern with a 10-second timeout. Both implementations call `clearTimeout(timeoutId)` in the try block after success and in the catch block to prevent memory leaks.

Retry logic in `briefDrafter.ts` runs exactly twice: initial attempt plus one retry on failure. No exponential backoff, no infinite loops. If both attempts fail (timeout, validation error, or network failure), the function returns a fallback brief generated by `generateFallbackBrief()`. The fallback uses rule-based keyword detection from the user's original idea—no AI call, no simulated success flag.

User content is treated as untrusted. The brief drafter sends only the `idea` string to Gemini, not the full user session or profile. The creator matcher sends compact summaries (content type, style, tools) rather than raw database rows. No SQL injection vectors exist because all database queries use parameterized Supabase client calls.

## Rate limiting scope and implementation

The rate limiter in `/lib/ai/rateLimit.ts` uses an in-memory Map storing arrays of timestamps per `userId:endpoint` key. The `checkRateLimit` function filters out timestamps older than the window (default 60 seconds), counts remaining entries, and rejects if the count exceeds the limit (default 10). On rejection, it calculates `retryAfterMs` as the difference between the oldest timestamp in the window plus the window duration and the current time.

Rate limiting is called in two API routes: `/api/brief` (brief drafting) and `/api/briefs/[id]/matches` (creator matching). Both extract `userId` from the session cookie, call `checkRateLimit(userId, endpoint, 10, 60000)`, and return a 429 response with `retryAfterMs` if rejected. Standard CRUD routes (`/api/briefs`, `/api/proposals`, `/api/creators`) do not call rate limiting—they rely on database RLS policies and Supabase's built-in protections.

The in-memory implementation resets on server restart. In a multi-node deployment, each instance maintains separate state, so a user could exceed the limit by distributing requests across nodes. The implementation is sufficient for a hackathon demo but should be replaced with Redis or a database-backed solution for production. The risk is bounded: the worst case is a user consuming more Gemini API quota than intended, not a security breach.

## Input preservation on provider failure

The `draftBrief` function returns a `DraftResult` type with four fields: `brief` (the structured output), `source` ('gemini' | 'fallback' | 'deterministic'), `aiLabeled` (boolean), and `preservedIdea` (the original user input). Every return path populates `preservedIdea: idea`.

When Gemini succeeds and passes validation, the function returns `{ brief: { ...parsed, generatedByAI: true, rawIdea: idea }, source: 'gemini', aiLabeled: true, preservedIdea: idea }`. When Gemini fails (timeout, network error, or validation failure), the function returns `{ brief: generateFallbackBrief(idea), source: 'fallback', aiLabeled: false, preservedIdea: idea }`. When no API key is configured, it returns the fallback immediately with `source: 'deterministic'`.

The `/api/brief` route extracts `preservedIdea` from the result and includes it in the JSON response alongside `brief`, `source`, and `aiLabeled`. The client receives the original idea even if the provider fails. No code path loses user input.

## Brief validation checks

`BriefIntelligence.tsx` implements 14 deterministic checks across three severity levels. Errors include missing title, objective, style, budget, and invalid budget range (min > max). The Part 3 addition flags Short-form Video with `durationSeconds > 60` as contradictory—this fires only when both conditions are met, not for Long-form Video or Brand Film with long durations.

Warnings cover missing aspect ratios, license tier, usage regions, preferred tools, and deadline. The Part 3 enhancement adds a check for exclusivity requested without usage regions specified. Another new check detects briefs with deadline < 7 days and budget < $1000, labeled explicitly as an estimate: "⚠️ Estimate only (assumptions: 1 creator, standard delivery): tight deadline and low budget may limit creator availability."

Suggestions recommend model indemnity for commercial campaigns, negative keywords to prevent unwanted content, and revision allowances in the objective or style fields. The revision check searches for the word "revision" in `objective.toLowerCase()` and `style.toLowerCase()`—if absent, it suggests stating how many revision rounds are included.

The multi-format brief handling issue mentioned in the review prompt has been correctly addressed: the code does NOT flag multiple aspect ratios with quantity > 1 as contradictory. The comment in line 99 states "Part 3: Multi-format validity - DON'T flag as contradictory when quantity > 1 and multiple aspect ratios" and confirms no warning exists for this case. A brief requesting 3 deliverables in both 16:9 and 9:16 is valid—the system treats it as separate variants.

## Creator matching scoring logic

The `matchCreators` function in `/lib/ai/creatorMatcher.ts` builds a score from four factors, each with a maximum point value. Skills overlap (40 pts max) divides the count of matched tools by the count of required tools. If the brief requires [Midjourney, Runway, Pika] and the creator has [Midjourney, Runway], the factor scores (2/3) * 40 = 27 points. If no tools are required, the factor awards full points.

Verified tools (30 pts max) matches `brief.toolsPreferred` against the names in `creator.verifiedTools[]`. Budget fit (20 pts max) estimates project cost as `hourlyRateUsd * 40` and compares to the brief's budget range. If the estimate falls within range, 20 points. If within 120% of max, 10 points. If over 150% of max, 0 points and a mismatch entry is added. Availability (10 pts max) awards 10 for "Available", 5 for "Limited", 0 for "Booked", and 0 for unknown with a missing evidence note.

The total score is `(sum of points / 100) * 100`, rounded. A creator matching 2 of 2 required tools, 1 of 2 verified, budget fit, and available status scores 40 + 15 + 20 + 10 = 85/100.

Portfolio matching iterates the creator's portfolio array, checking if `item.contentType === brief.contentType` or if any `item.toolsUsed` appear in `brief.toolsPreferred`. Matched items are pushed to `matchedPortfolioItems[]` with `id`, `title`, `mediaUrl`, `thumbnailUrl`, and `relevance` (a human-readable explanation like "Same content type: Short-form Video" or "Uses required tools: Midjourney, Runway"). The function never creates new portfolio items, never invents URLs, never fabricates verification status.

Unknown data is treated as unknown. If `creator.availability` is null or undefined, the availability factor scores 0 points and adds "Availability unknown" to `missingEvidence[]`. If `creator.verifiedTools` is empty, the verified tools factor scores 0 and explains "0 verified tools matching brief: none". The system does not assume unknown means bad—it flags it as missing information.

## AI qualitative notes as optional enhancement

If `process.env.GEMINI_API_KEY` is present, `matchCreators` calls `getAIQualitativeNote(brief, creator)` for each match. The function sends a compact summary (not full records) to Gemini with a 10-second timeout and requests a brief qualitative assessment in plain text (not JSON). The response is validated: must be a string, non-empty, under 500 characters. If valid, it's prepended with "[AI assessment]" and stored in `match.aiNote`. If the call times out, returns invalid data, or the API key is missing, `aiNote` remains `undefined` and `aiLabeled` is `false`.

The deterministic score and factor breakdown are always calculated. The AI note is additive—if it fails, the match is still usable. The UI shows a "Deterministic Baseline" badge when no matches have `aiLabeled: true`, and an "AI-Assisted" badge when `aiLabeled` is true. The AI note appears in a purple-bordered section labeled "AI Assessment" inside the expanded details.

## Type exports and imports

The types `CreatorMatch`, `MatchFactor`, and `PortfolioMatch` are exported from `/lib/ai/creatorMatcher.ts`, not from `/types/index.ts`—they're specific to the matching algorithm, not part of the core domain model. Core types (`Brief`, `CreatorProfile`) are imported from `@/types`. No circular dependencies, no missing exports.

## Integration into user journey

Brief drafting is exposed via `POST /api/brief` during brief creation—no standalone chatbot. Brief validation appears as the `<BriefIntelligence>` component in brief creation/editing forms. Creator recommendations appear on `/briefs/[id]` via `<CreatorMatches>`, visible only to the brand owner. The matches endpoint verifies ownership before running the algorithm and returns the top 10 matches with score, factor breakdown, portfolio thumbnails, mismatches, missing evidence, and action buttons. The invite flow connects to existing proposal submission.
