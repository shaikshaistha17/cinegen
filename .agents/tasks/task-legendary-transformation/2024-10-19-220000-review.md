## Graceful fallback architecture in data hooks

All six data hooks (useCreators, useBriefs, useProposals, useMessages, useReviews, useVerifications) check Supabase configuration at runtime via `isSupabaseConfigured()` which tests for `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_ANON_KEY` environment variables. When unconfigured, hooks return seed data immediately and skip database queries entirely.

**useCreators** initializes state with seedCreators, then conditionally fetches from Supabase only when configured. On error, it logs a warning and preserves seed data rather than failing. The hook subscribes to real-time changes only when Supabase is available. Mutations (create, update, upload) throw "Supabase not configured" errors when unavailable, which is correct since demo mode is read-only.

**useBriefs** combines seed data with localStorage for user-created briefs when Supabase is unavailable. The fetchBriefs callback checks configuration first, falling back to `storage.read<Brief[]>(KEY)` and merging with seedBriefs. Save operations write to localStorage in demo mode, preserving user work within the browser session. This hybrid approach supports the demo flow where users can create and publish briefs even without a backend.

**useProposals** follows the same localStorage fallback pattern. The submitProposal callback generates temporary IDs (`prop_${Date.now()}`) in demo mode and stores them locally. This enables the full proposal flow in demos: creators can submit proposals, brands can see them, and status updates work via localStorage.

**useMessages** returns empty arrays when Supabase is unconfigured since messaging requires server-side conversation tracking and real-time sync. The hook includes polling fallback if Realtime subscription fails, switching to 10-second intervals to ensure messages eventually arrive even if WebSocket connections are blocked.

**useReviews** and **useVerifications** require Supabase for write operations and return empty/null for reads when unconfigured. Reviews need database persistence for aggregate rating calculations, and verifications need admin workflows that don't make sense in demo mode.

All hooks log fallback events to console.warn rather than console.error, signaling degraded functionality without alarming users.

## Demo login and session management

The useSession hook manages both Supabase authentication and demo sessions. Demo credentials are hardcoded as brand@cinegen.demo and creator@cinegen.demo with password Demo@123. The login function calls `/api/auth/login` which detects demo emails and returns a session object without database access.

Global listeners are implemented via a Set of callback functions, allowing all components using useSession to update simultaneously when auth state changes. This prevents stale session data in split views like the Navbar and Dashboard running side-by-side.

The convertAuthSessionToSession helper fetches user role and profile IDs from the database for real users, but falls back to metadata for demo users. Demo sessions include `{ userId, email, role, name, loginAt }` plus optional `creatorId` or `brandId` fields depending on role.

Session persistence uses cookies (cinegen_role) with 7-day expiration and SameSite=Lax, enabling role-based redirects on page load without database queries. The logout function clears both Supabase auth and the local session state, then forces a full page reload to ensure clean state.

The loginAsRole helper provides one-click demo login, used on the landing page to let users jump into either brand or creator views instantly.

## Glassmorphism design system implementation

Three glassmorphism classes are defined in globals.css:

- `.glass`: rgba(255,255,255,0.03) with 12px blur, used for general overlays
- `.glass-strong`: rgba(255,255,255,0.1) with 20px blur, used for Navbar and dropdowns  
- `.glass-card`: rgba(255,255,255,0.05) with 16px blur, used for cards and panels

All include backdrop-filter and -webkit-backdrop-filter for Safari support, with border: 1px solid rgba(255,255,255,0.08-0.12) creating subtle edge definition.

**Navbar** uses glass-strong on the sticky nav container with inline style `background: rgba(10,10,15,0.95)` for additional density. The tools dropdown also uses glass-strong for the floating menu overlay.

**Dashboard** applies glass-card to stat cards (projects, revenue, hours, clients), engagement metrics cards, brief cards, and proposal cards. The grid layouts maintain consistent glass-card usage across all dashboard sections for both brand and creator views.

**CreatorCard** uses glass-card as the base with inline `background: rgba(255,255,255,0.05)` and `backdropFilter: blur(16px)`, plus an animated gradient border on hover that transitions from opacity 0 to 100 over 500ms. The preserve-3d transform and rotateX/rotateY based on mouse position create a 3D tilt effect.

**AI Brief Builder** applies glass to all form sections (Campaign Details, Content Specs, Budget & Timeline, Licensing, Advanced Options) and the completeness bar container. The AI mode panel uses `glass rounded-2xl border border-violet-500/20` to distinguish it from manual mode sections. Published brief success screen uses glass for the top match cards.

Gradient overlays combine with glassmorphism: many cards include `<div className="absolute inset-0 bg-gradient-to-br from-violet-600/5 to-transparent opacity-0 group-hover:opacity-100 transition-opacity duration-300" />` for hover depth without obscuring content.

## Animation system and visual feedback

tailwind.config.ts defines 11 animations with keyframes:

- **gradient-x** (4s infinite): background-position shift from 0% to 100%, used on hero gradients
- **pulse-slow** (4s cubic-bezier infinite): custom pulse timing for breathing effects
- **float** (6s ease-in-out infinite): translateY(-10px) at midpoint for floating icons
- **glow** (2s ease-in-out infinite): box-shadow intensity oscillation for focus effects
- **float-slow** (8s): translateY(-20px) translateX(10px) for slower drift
- **shimmer-slow** (3s linear infinite): background-position sweep for loading states
- **gradient-shift** (8s ease-in-out infinite): 4-point background-position path for gradient flow
- **pulse-glow** (2s cubic-bezier infinite): layered box-shadow pulse for online status indicators
- **fade-in-up** (0.6s forwards): opacity 0→1 + translateY(20px)→0 for page entrance
- **scale-in** (0.4s forwards): opacity 0→1 + scale(0.9)→1 for modal entrance
- **slide-in-right** (0.5s forwards): opacity 0→1 + translateX(20px)→0 for sidebar items

Framer Motion animations are layered on top: CreatorCard uses staggered initial={{ opacity: 0, y: 20 }} with delay: index * 0.04 for cascading card reveal. Dashboard stat cards use whileHover={{ y: -4, scale: 1.02 }} for interactive lift. AI Brief Builder field population uses setTimeout chains with 200ms intervals to simulate streaming.

Visual score rings on creator match results use SVG circle with stroke-dasharray set to match score, creating a circular progress indicator without dependencies. Score-based color mapping (≥80: violet, ≥60: cyan, else: amber) provides instant visual feedback on match quality.

The navbar active link uses layoutId="navbar-underline" on a motion.div for a smooth sliding underline effect that transitions between nav items without jump. Completeness bar in brief builder animates width changes over 500ms with color transitions from violet→amber→green as score increases.

Tool-specific color coding in CreatorCard assigns each AI tool a unique bg/text color pair (Runway: blue, Midjourney: violet, Kling: pink, Sora: cyan, etc.) creating visual variety and instant recognition in tool badge grids.
